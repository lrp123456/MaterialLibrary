# 系统性能测量指标体系与基准采集规范

- **版本**：v1.0.0
- **发布日期**：2026-11-04
- **适用范围**：App 移动端、Web 前端工作台及后端 API 服务
- **责任归属**：性能工程与稳定性保障专项组

---

## 1. 规范定位与目标

为支撑 MaterialLibrary 系统的持续演进与架构优化，本规范建立了一套**跨 App 端、Web 端及后端服务的标准化性能测量指标体系（SLI/SLO）**，统一各端的性能统计口径，并提供标准化、免外部依赖的自动化基准采集工具集与埋点探针。

本规范的核心目标：
1. **统一测量口径**：明确定义 App 冷热启动、探活、渲染、帧率、Core Web Vitals、后端 TTFB、QPS 等各关键指标的起止打点时机；
2. **沉淀现网基线**：记录系统在当前生产运行环境下的真实实测基线（Baseline），为后续每一项优化整改提供精准的量化对比参照；
3. **固化验证工具**：提供 App 端 `PerfTracker.js`、Web 端 `web-vitals-collector.js` 以及后端 `scripts/benchmark_backend.js` 的完整源码与使用指引，确保优化成果可独立测量、可自动化复验。

## 2. 全链路性能指标体系与统计口径定义

### 2.1 App 移动端性能指标口径

| 性能指标 | 指标标识 | 起始打点时机 | 终止打点时机 | 统计口径说明与计算公式 | 优良阈值 (Good) | 达标上限 (Target) |
|:---|:---|:---|:---|:---|:---:|:---:|
| **冷启动全流程耗时** | `APP_COLD_LAUNCH` | `App.vue: onLaunch` 第一行代码执行 | 首屏 `browse.vue: onReady` 后调用 `$nextTick` | 覆盖原生引擎初始化、JS 评估、网络探活与首屏第一帧真实可见的完整耗时 | $< 600\text{ms}$ | $\le 800\text{ms}$ |
| **热启动唤醒耗时** | `APP_WARM_RESUME` | `App.vue: onShow` 入口 | 顶层活动页面完全恢复交互时 | 从后台切回前台至界面可响应点击的耗时 | $< 120\text{ms}$ | $\le 180\text{ms}$ |
| **网络探活决断耗时** | `NET_PROBE_COST` | `ensureServerUrl` 启动探测 | 确定并持久化首个可用地址到内存时 | 遍历探测候选服务地址链到最终定案的耗时 | $< 80\text{ms}$ | $\le 150\text{ms}$ |
| **首屏素材列表加载** | `PAGE_BROWSE_LOAD` | `browse.vue: reload` 发起请求 | 收到响应且完成卡片 `mapServer` 映射 | 包含 HTTP 传输 + JSON 反序列化 + 卡片属性映射的耗时 | $< 250\text{ms}$ | $\le 350\text{ms}$ |
| **详情页路由瞬开耗时** | `DETAIL_OPEN_LATENCY` | 列表点击卡片触发 `openDetail` | `detail.vue` 挂载并渲染出首帧预览图 | 路由动画转场 + 消费预览预热数据至首帧呈现的耗时 | $< 50\text{ms}$ | $\le 100\text{ms}$ |
| **相册千张扫描耗时** | `ALBUM_SCAN_1K` | `AlbumScanner.scanAlbum` 入口 | MediaStore 游标遍历结束并去重完 | 扫描系统相册并构建元数据数组的耗时（归一化为每 1000 张） | $< 100\text{ms} / 1\text{k}$ | $\le 150\text{ms} / 1\text{k}$ |
| **长列表滑动帧率** | `SCROLL_FPS` | 连续滑动屏幕触发滚动事件 | 停止滚动后 500ms 采样窗口结束 | $\text{FPS} = \frac{\text{帧数}}{\text{滑动持续时间 (s)}}$，考察主线程是否掉帧 | $\ge 58\text{ FPS}$ | $\ge 55\text{ FPS}$ |

### 2.2 Web 前端性能指标口径（含 Core Web Vitals）

|:---|:---|:---|:---|:---:|:---:|

| **长任务发生频次** | **Long Tasks** | `PerformanceObserver` 监听 `longtask`（持续时间 $>50\text{ms}$） | 统计主线程被长任务独占的总次数与峰值时长 | $0\text{ 次}$ | 单次 $\le 60\text{ms}$ |

### 2.3 后端 API 与服务性能指标口径

| 性能指标 | 指标标识 | 采集方式与标准 | 统计口径说明与计算公式 | 优良阈值 (Good) | 达标上限 (Target) |
|:---|:---|:---|:---|:---:|:---:|
| **API 首字节延时 (P95)** | **TTFB P95** | 高并发压力测试，统计客户端收到首字节耗时 | 95% 的请求在指定毫秒内收到服务端的 HTTP Headers | $< 3.0\text{ms}$ | $\le 5.0\text{ms}$ |
| **API 总响应延时 (P95)** | **Total Latency P95** | 高并发压力测试，统计完整接收响应体耗时 | 95% 的请求在指定毫秒内完成传输与解压 | $< 5.0\text{ms}$ | $\le 8.0\text{ms}$ |
| **资产分页吞吐量** | **Assets QPS** | 10 并发下针对 `/assets?page=1&pageSize=24` 压测 | $\text{QPS} = \frac{\text{成功总请求数}}{\text{压测持续总时间 (s)}}$ | $> 1500\text{ QPS}$ | $> 1200\text{ QPS}$ |
| **小图流式安全首图延迟** | **Grid Stream Latency** | 请求 `/api/viewer/assets/:fid/image?tier=grid` | 从发送请求到收到第一张 256px 网格图的耗时 | $< 3.0\text{ms}$ | $\le 5.0\text{ms}$ |
| **流式断开无用 I/O 抑制率** | **Stream Abort Reduction** | 客户端只读 64KB 后立即 destroy 验证读盘消耗 | $1 - \frac{\text{安全流读盘量}}{\text{原生管道全量体积}}$，考察流安全销毁率 | $\ge 90.0\%$ | $\ge 85.0\%$ |
| **后台任务调度扫描** | **Worker Scan Cost** | 解释器 `processNextBatch` 轮询耗时 | 扫描并提取下一个就绪 `node_runs` 任务的单次 SQL 执行耗时 | $< 0.2\text{ms}$ | $\le 0.5\text{ms}$ |
| **长任务调度阻塞率** | **Scheduler Block Rate** | 统计耗时 AI 任务运行期间，普通任务排队超时的比率 | $\frac{\text{被串行锁挂起超时的任务数}}{\text{提交总任务数}} \times 100\%$ | $0\%$ | $0\%$ |

## 4. 自动化基准采集工具与探针代码及部署指引

### 4.1 App 端性能打点探针 (`PerfTracker.js`)

在移动端工程中注入轻量级、低损耗的性能打点工具，挂载于 `app-uniapp/src/service/PerfTracker.js`：

```javascript
/**
 * App 性能测量与打点监控基础设施 (PerfTracker.js)
 * 纯原生、无依赖、高精度时间戳记录，零垃圾回收负担。
 */
class PerfTracker {
  constructor() {
    this.startTimes = new Map();
    this.records = [];
  }

  // 开始打点
  start(metricKey) {
    this.startTimes.set(metricKey, Date.now());
  }

  // 结束打点并结算耗时
  end(metricKey, extra = {}) {
    const t0 = this.startTimes.get(metricKey);
    if (!t0) return null;
    const duration = Date.now() - t0;
    this.startTimes.delete(metricKey);

    const record = {
      metric: metricKey,
      duration,
      timestamp: Date.now(),
      ...extra
    };
    this.records.push(record);

    // 标准格式化控制台输出，便于自动化测试抓取
    console.log(`[PERF_TRACKER] ${metricKey}: ${duration}ms`, extra);
    return duration;
  }

  // 获取所有历史指标记录
  getMetrics() {
    return [...this.records];
  }

  // 清空记录
  clear() {
    this.records = [];
    this.startTimes.clear();
  }
}

export const perfTracker = new PerfTracker();
```

#### 使用埋点规范示例
```javascript
// 1. App 冷启动打点 (App.vue)
import { perfTracker } from './service/PerfTracker.js';
onLaunch(() => {
  perfTracker.start('APP_COLD_LAUNCH');
});

// 首屏呈现后结算 (browse.vue)
onReady(() => {
  this.$nextTick(() => {
    perfTracker.end('APP_COLD_LAUNCH');
  });
});

// 2. 探活打点 (ServerResolve.js)
perfTracker.start('NET_PROBE_COST');
const activeUrl = await probeCandidates();
perfTracker.end('NET_PROBE_COST', { activeUrl });

// 3. 相册扫描打点 (AlbumScanner.js)
perfTracker.start('ALBUM_SCAN_1K');
const mediaList = await readCursor();
perfTracker.end('ALBUM_SCAN_1K', { count: mediaList.length });
```

### 4.2 Web 端性能采集探针 (`web-vitals-collector.js`)

在 `web-pro/src/utils/` 与 `web/src/utils/` 部署原生 Web Vitals 采集探针，无缝支持 Core Web Vitals 与 Long Tasks 监控：

```javascript
/**
 * Web 端体验指标与长任务自动化采集探针 (web-vitals-collector.js)
 * 基于原生 PerformanceObserver 与 Navigation Timing 规范构建。
 */
export class WebVitalsCollector {
  constructor(options = {}) {
    this.appName = options.appName || 'web-pro';
    this.reportUrl = options.reportUrl || '/api/metrics/web-vitals';
    this.metrics = {
      nav: {},
      vitals: {},
      longTasks: [],
      custom: {}
    };
    this.init();
  }

  init() {
    if (typeof window === 'undefined' || !window.performance) return;

    // 1. 页面加载完成时采集导航时序
    window.addEventListener('load', () => {
      setTimeout(() => this.collectNavigationTiming(), 0);
    });

    // 2. 观察 Core Web Vitals (FCP, LCP, CLS)
    this.observeVitals();

    // 3. 观察主线程长任务 (Long Tasks > 50ms)
    this.observeLongTasks();
  }

  collectNavigationTiming() {
    const entries = performance.getEntriesByType('navigation');
    if (!entries || !entries.length) return;
    const nav = entries[0];

    this.metrics.nav = {
      dnsTime: Math.round(nav.domainLookupEnd - nav.domainLookupStart),
      tcpTime: Math.round(nav.connectEnd - nav.connectStart),
      ttfb: Math.round(nav.responseStart - nav.requestStart),
      downloadTime: Math.round(nav.responseEnd - nav.responseStart),
      domReadyTime: Math.round(nav.domContentLoadedEventEnd - nav.fetchStart),
      loadComplete: Math.round(nav.loadEventEnd - nav.fetchStart),
      transferSize: nav.transferSize || 0
    };
    this.flush();
  }

  observeVitals() {
    // FCP
    try {
      const fcpObserver = new PerformanceObserver((list) => {
        for (const entry of list.getEntries()) {
          if (entry.name === 'first-contentful-paint') {
            this.metrics.vitals.fcp = Math.round(entry.startTime);
            fcpObserver.disconnect();
            break;
          }
        }
      });
      fcpObserver.observe({ type: 'paint', buffered: true });
    } catch (_) {}

    // LCP
    try {
      const lcpObserver = new PerformanceObserver((list) => {
        const entries = list.getEntries();
        const lastEntry = entries[entries.length - 1];
        if (lastEntry) {
          this.metrics.vitals.lcp = Math.round(lastEntry.startTime);
        }
      });
      lcpObserver.observe({ type: 'largest-contentful-paint', buffered: true });
    } catch (_) {}

    // CLS
    try {
      let clsValue = 0;
      const clsObserver = new PerformanceObserver((list) => {
        for (const entry of list.getEntries()) {
          if (!entry.hadRecentInput) {
            clsValue += entry.value;
            this.metrics.vitals.cls = Number(clsValue.toFixed(4));
          }
        }
      });
      clsObserver.observe({ type: 'layout-shift', buffered: true });
    } catch (_) {}
  }

  observeLongTasks() {
    try {
      const observer = new PerformanceObserver((list) => {
        for (const entry of list.getEntries()) {
          this.metrics.longTasks.push({
            startTime: Math.round(entry.startTime),
            duration: Math.round(entry.duration)
          });
          // 保留最近 20 条长任务
          if (this.metrics.longTasks.length > 20) this.metrics.longTasks.shift();
        }
      });
      observer.observe({ type: 'longtask', buffered: true });
    } catch (_) {}
  }

  // 业务耗时打点（如 Tab 切换延迟）
  measureCustom(name, durationMs) {
    this.metrics.custom[name] = Math.round(durationMs);
    this.flush();
  }

  flush() {
    if (typeof navigator !== 'undefined' && navigator.sendBeacon) {
      const payload = JSON.stringify({
        app: this.appName,
        timestamp: Date.now(),
        metrics: this.metrics
      });
      navigator.sendBeacon(this.reportUrl, payload);
    }
  }
}

export const vitalsCollector = new WebVitalsCollector({ appName: 'material-studio-pro' });
```

### 4.3 后端自动化基准测试工具 (`scripts/benchmark_backend.js`)

#### 工具特性
- **零外部依赖**：仅基于 Node.js 原生 `http`、`https` 与 `perf_hooks` 模块构建，克隆即可运行；
- **多维度度量**：自动计算 P50、P90、P95、P99、QPS、成功率以及平均传输包体大小；
- **全场景接口覆盖**：包含心跳探活、高频字典树、聚合统计以及不同入参的分页资产检索；

1. **移动端发版门禁**：
   - 真实真机冷启动至首屏呈现耗时不得超过 **800ms**；
   - 1000 张相片全量扫描去重耗时不得超过 **200ms**；
   - 列表长滑动平均帧率不得低于 **55 FPS**；
   - 生产包体积不得包含未引用的历史冗余静态模型/脚本文件。
2. **Web 端发版门禁**：
   - Core Web Vitals 验收：FCP $\le 800\text{ms}$，LCP $\le 1.8\text{s}$，CLS $\le 0.08$；
   - 输入框持续打字期间 Long Tasks 必须为 **0 次**；

3. **后端 API 发版门禁**：
   - 执行 `node scripts/benchmark_backend.js --concurrency=10 --requests=50`；
   - `/health`、`/dict/menu-tree`、`/stats` 的 P95 响应耗时必须低于 **10ms**；
