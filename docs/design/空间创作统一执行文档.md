## 3. 阶段 1：页面骨架

目标：一个页面里完成看图、编号、一次挂载。此阶段不搬移精准编辑工具。

### 3.1 结构

`StudioView.vue` 去掉 `activeSub` 二级菜单，只渲染对话页。`initialPayload.target === 'quick'` 时也不要切走，改为打开右抽屉并把图挂上。

对话页三列：

- 左抽屉：现有对话历史。默认展开，可收起。收起后中间变宽。
- 中间：上面是消息滚动区，中间是看图区，下面是输入框。输入框固定在底部。
- 右抽屉：默认关闭。此阶段只放标题「精准编辑」和一句「工具在后续阶段接入」。不要把 `QuickStudio` 整页放进来。

消息上现有的「精准重绘」改为：把该图挂进看图区，并打开右抽屉。

### 3.2 看图区

- 看图区展开时约占中列七成，高度固定。拼法、底条、点按规则写在 `docs/design/空间创作页面设计.md`。不要做左右箭头轮播，不要把每张图塞进同一个 4:5 槽。
- 图号在画面下方，文件名再小一号。
- 此阶段点大图进入的编辑层只显示「编辑工具在阶段 3 接入」和「放弃」。不要做裁剪。
- 添加在底条末尾，打开素材选择器。
- 已发送消息在看图区上方，向上滚动查看。
- 视频和音频不进看图区和底条，只作为输入框芯片。

发送之后：看图区里的图保留。配方句和补充句清空，并出现在刚发出的消息里。不要再执行 `referenceTray = []`。

### 3.3 图号与 `@`

- 编号按挂上的顺序，第一张是图 1。左右转动不改变编号。
- 输入框芯片文字是 `图N`。
- 输入 `@` 时，若看图区已有图，先弹出列表：缩略图 + `图N`。点一项，在光标处插入芯片。列表底部是「从素材库添加」，才打开选择器。一张图都没有时，`@` 仍直接打开选择器。
- 删除中间一张后，后面的编号前移。配方句、补充句、芯片里的 `@图N` 同步修改。

### 3.4 选图

`AssetPickerModal` 增加属性 `commitOnVersion`。只有对话页传入 `true`。

- `commitOnVersion` 为真：点一个已有版本，立刻把该版本交给父组件并关闭。点虚线的缺失画幅时才生成，成功后挂上并关闭，失败则留在选择器并显示错误。不要「完成」，不要「确认挂载」。
- 其他调用方保持原来的确认按钮。

本地上传：选完文件就挂上并关闭。行为已在 `onAssetPickerUpload`，保持。

### 3.5 素材库送入

`handleSendToChatFromModal`、列表上的送入、`handleBatchSendToChat` 都传正式图 URL：`getAssetImageUrl` 或当前衍生图 URL。不要用 `getThumbnailSrc`。卡片封面仍用缩略图。

对话页收到后：

- 把图追加到看图区，不替换已有的图。
- 在光标处插入芯片。
- 不写配方句，不覆盖补充句，不写入「参考空间结构与采光」这类固定句。
- `mountAssetFromLibrary` 里清空 `innerHTML` 的逻辑删掉。

### 3.6 验收

- 顶部没有二级菜单。
- 从素材详情进入后，看图区出现当前版本的正式图，输入框原有文字还在，并多了一个 `图N` 芯片。
- 选择器点 9:16 后直接回到对话，中间没有第二次确认。缺失档会生成，生成中有等待，失败有错误。
- 一张图居中尽量大。两张一横一竖时，竖图窄列、横图占剩余宽度，都不裁切。四张时看图区高度不变，多出来的在看图区内滚动。
- 底条始终在看图区下面。收缩后看图区消失，底条还在。点底条只展开并选中，不进入编辑。
- 发送后图还在看图区。
- 删掉图 1 后，原图 2 变成图 1，句子里的 `@图2` 变成 `@图1`。
- 视频挂载不出现在看图区。

## 4. 阶段 2：配方句、三种全局操作、请求预览

### 4.1 输入框

分成两块，都可编辑：

- 上：配方句。右抽屉写入，用户可改。
- 下：补充句。只有用户输入，或阶段 6 的建议填入。

发送正文 = 配方句 + 换行 + 补充句。空块跳过。

右抽屉更换风格或操作时，只替换配方句。补充句保留。

出图画幅只用输入框现有的清晰度和比例控件。右抽屉不要再放一套画幅。

发送时不要带 `auto_optimize: true`。优化只来自用户点击「优化提示词」，而且优化结果先写回输入框，再由用户发送。

### 4.2 右抽屉里的三个全局操作

风格、超分、去水印。选中后写配方句，发送走 `POST /api/gen/images`。不要走 `POST /api/edit/run` 的 `style_transfer`、`clarity`、`remove`。

风格列表复用 `QuickStudio.vue` 的 `officialStyles` 和自定义风格接口 `fetchCustomStyles`。用户能改风格锚定描述。描述写进配方句，发送的就是这句。

配方句模板，花括号是替换位，写完后用户仍可改字：

- 风格：`将@图1改为{风格名}。{风格锚定描述}。保持原有空间结构、构图和主要家具位置。`
- 超分：`将@图1的清晰度提升到{档位}。只增强清晰度，不改变构图、物体、材质和颜色。`
- 去水印：`去除@图1中的水印和标识。其余画面保持不变。`

多张图时，模板里的 `@图N` 用当前点中的那张。未点中时用图 1。

### 4.3 优化约束

在 `POST /api/chat/optimize-prompt` 的 `userMsg` 增加一段硬约束，保留原有模型技能，不要替换掉 `polish.prompt`：

- 同时看本次传入的图片、配方句和补充句。
- 只能把话说清楚。
- 必须保留：物体、颜色、方向、用户写的 `@图N`、框和箭头的含义、操作名称、角度数字。
- 禁止把「沿红箭头移动」改成另一种操作。
- 禁止把用户的 `@图N` 改成 `@图片N`、`<Picture N>` 或「参考图」。方言转换只发生在真正提交给供应商时。

客户端继续用 `optimizeUndo`。撤回恢复两段原文。

### 4.4 请求预览与请求记录

新增 `POST /api/gen/preview`。它复用 `/api/gen/images` 在调用供应商之前的组装：`prepareGovernedSubmit` 和 `compileModelDialect`。禁止复制一份方言规则。此接口不调用适配器，不生成图片。

预览和真实发送必须经过同一个客户端函数，保证两处看到的正文一致。该函数要包含现在的 `carryPriorRefs` 和 `promptWithPriorAnalysis`。不要再增加新的隐藏后缀。

返回并展示四块：

1. 你写的原文。
2. 方言编译后的正文。
3. 图列表。每项有 `图N`、来源 `stage` 或 `history`、去掉 query 后的 URL 路径。
4. 请求头、JSON 正文、curl。

脱敏：`Authorization`、任何 api key、URL query 里的 `token` 显示为 `***`。curl 里的 key 写成 `$API_KEY`。图片路径保留，否则无法核对有没有挂上。

发送成功后，把这份快照写进该用户消息的 `params.outbound`。重新打开会话，从 `params.outbound` 读出「请求」。不要只存在前端内存里。

输入框旁放「预览请求」。已发送消息上放「请求」。

### 4.5 验收

- 选一个风格后，只有配方句变化。补充句还在。
- 改几个字再发送，供应商侧正文里能看到改过的字。预览里的编译结果和实际发送一致。
- Agnes 模型的预览把 `@图1` 显示成 `<Picture 1>`，输入框里仍是 `@图1`。
- 看图区为空时发送，预览的图列表来源是 `history`，并显示被追加的那句分析。
- 请求里看不到 key 和 token 原文。
- 刷新页面后，旧消息仍能打开「请求」。
- 风格操作的网络请求是 `/api/gen/images`，不是 `/api/edit/run`。

## 5. 阶段 3：自定义编辑

从看图区进入。工具：裁剪、马赛克、矩形框、箭头、文字。画在副本上，不改原图字节，直到用户确认。

退出对话框两个按钮：「使用编辑后的图片」「仍用原图」。

- 使用：这张 `图N` 的显示和发送都换成编辑版。卡片上保留一次「撤回到原图」。
- 仍用原图：丢弃这次绘制。

不自动写配方句。用户自己在补充句或配方句里描述红框和箭头。

同一次发送只允许一种模式。进入自定义时，清掉这张图上尚未确认的预定操作。已经确认并写进配方句的，保持不动，直到用户再选一个预定操作覆盖配方句。

标注图不要上传入库。它只作为这次发送的图片字节或临时 URL。

### 验收

- 裁剪后选「仍用原图」，看图区回到裁剪前。
- 选「使用编辑后的图片」再预览请求，图列表指向编辑后的图，原图还能撤一次。
- 画了红箭头但没写字，配方句不会自己出现一段说明。
- 马赛克是像素，不是一层可被发送时丢掉的矢量。

## 6. 阶段 4：预定空间操作

右抽屉放入：替换、增加、安装、留白、去除、扩图。画布在看图区当前图上。参数在右抽屉。一步一步的短句也在右抽屉，例如「先框出要替换的区域」。

这些操作发送走 `POST /api/edit/run`，沿用 `QuickStudio.vue` 里已有的字段：`op`、`region`、`refImage`、`productImage`、`modelYaw`、`modelPitch`、`gapPct`、`prompt`。`prompt` 用用户改过的配方句，不要用文件里的固定英文或固定中文。

完成时的对话框：「使用这套操作」「放弃」。放弃不改配方句。使用则写入下面的模板。

- 替换：`在@图1的框选区域，把该物体替换为{家具名}。朝向与家具参考图一致，左右{yaw}度，上下{pitch}度。框外画面保持原图像素。`
- 增加：`在@图1的框选区域新增{家具名}。朝向与家具参考图一致，左右{yaw}度，上下{pitch}度。不要遮挡框外已有物体。`
- 安装：`在@图1的框选区域安装{产品名}。外观以产品参考图为准。框外画面保持原图像素。`
- 留白：`把@图1框选区域附近的物体间距拉开约{gap}。被拉开的物体保持原样，其余画面不变。`
- 去除：`去掉@图1框选区域中的物体，用周围的墙面、地面和光影补齐。框外保持原图像素。`
- 扩图：`把@图1向{方向}扩展。原图已有内容保持不变，只补全新出现的区域。{用户写的扩展说明}`

替换和增加的朝向：

- 用户拉出一个区域，区域先铺白底。
- 3D 预览放在这块白底上，用现有滑条原地旋转。
- 拖动过程中只在本地转，不调用 `captureViewerSnapshot`。
- 用户完成时截一次。去掉黑底后，得到家具图。
- 屏幕上另存一张合成图，只给用户核对。
- 真正提交的是三份：干净原图、框、去掉黑底的家具图，加上配方句里的角度。合成图不作为模型输入，不入库。

安装不用 3D。产品照片放进框里。提交仍是原图、框、产品图。

卡片上能切换查看：原图、框、家具图或产品图、合成核对图。

阶段 4 验收通过后，`StudioView` 不得再挂载整页 `QuickStudio`。文件先留着，便于对照。不要删。

### 验收

- 拖动滑条时网络面板没有新的图片上传。松开并完成之后只有一次截图。
- 预览请求里的图片是原图和去背家具图，没有合成图。
- 配方句里的角度和滑条一致。改掉配方句里的一个词后再发送，`/api/edit/run` 的 `prompt` 是改后的句子。
- 框外贴回仍由现有编辑接口负责，不要新写贴回算法。

## 7. 阶段 5：换色

换色是预定模式的一项，不是自定义画笔。

### 7.1 服务端配色

新表，写在 `scripts/migrate.js`：

```sql
CREATE TABLE IF NOT EXISTS color_schemes (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  kind TEXT NOT NULL, -- scheme | swatch
  roles_json TEXT NOT NULL, -- scheme: [{role,name,hex}]  swatch: [{name,hex}]
  sort_order INTEGER NOT NULL DEFAULT 0,
  updated_at INTEGER NOT NULL
);
```

预置四条方案角色：墙面、顶面、地面、家具。再预置若干单色。具体色值写进迁移种子，设置页可以改。

接口：

- `GET /api/studio/color-schemes`
- `PUT /api/studio/color-schemes`
- 仅登录用户可写。沿用现有 `isViewerOrAdmin`。

`SettingsView.vue` 增加一节「换色预置」。可改名称、角色、色号。不要放到 `web/` 管理端。

### 7.2 画布

矩形四个角可单独拖动。拖动后不保持矩形。边的中点可加节点。点用归一化坐标 `0–1`，相对这张图。

右侧列表：`区域1：顶部墙面 — #F4F0E6`。名称和颜色可改。画面上用半透明填充预览。

手动：

1. 先选方案或单色。
2. 框闭合时调用一次识图，只给这个框起名。选了方案时，按返回的角色填该角色的色。
3. 用户可改名、改色。

自动：

1. 只有点击「识别」才调用一次识图。
2. 返回若干粗框和角色名。
3. 用同一套节点编辑。
4. 更换方案时只在本地按角色重配颜色，不再请求模型。

识图复用现有对话视觉模型的调用方式，不要新建供应商。提示词要求返回 JSON 数组：`[{ "name": "顶部墙面", "role": "顶面", "points": [[x,y],[x,y],[x,y],[x,y]] }]`。角色必须是方案里的 `role`。解析失败就提示重试，不要假装识别成功。

这一阶段不要接 EdgeSAM，也不要生成贴边遮罩。

配方句：

`按下列区域修改@图1的颜色，框外保持不变。区域1（{名称}）改为{色号}。区域2（{名称}）改为{色号}。`

发送走 `/api/edit/run`。在现有 body 上增加 `regions: [{ name, role, hex, points }]`。`prompt` 仍是用户改过的配方句。若当前 `edit/run` 忽略未知字段，在 `src/handlers/edit-run.js` 把 `regions` 和 `prompt` 传给已经在用的生图步骤。不要新开一条隐藏提示词。

### 7.3 验收

- 设置页改一个角色的色号后，创作页方案里是新色号。
- 手动框一个区域，只产生一次识图请求。
- 拖动一个角后，形状不再是矩形，预览请求里的 `points` 是拖动后的值。
- 自动识别后更换方案，网络面板没有新的识图请求，区域颜色跟着方案变。
- 半透明预览不是发送给模型的图片。

## 8. 阶段 6：建议提示词

两个入口，都写入补充句，不自动发送，不替换配方句。

1. 看图区按钮「按这些图给建议」。只有点击才请求。一次识图，返回三句。输入是当前显示的版本（编辑版优先）。
2. 助手消息成功写入后，自动请求一次「接着可以」。只送上一句助手正文，不送图片。失败消息和错误消息不请求。返回三句，显示在该条消息下方。

接口 `POST /api/chat/suggest-prompts`：

- `kind: "images"` 时必须有图片，走现有视觉模型。
- `kind: "next"` 时禁止附带图片。
- 返回 `{ suggestions: [string, string, string] }`。不足三句就按实际句数展示，不要补空话。

挂图、换图、转箭头都不触发这个接口。

### 验收

- 连换三张图，网络里没有建议请求。点击按钮后恰好一次。
- 点一句建议，文字出现在补充句，配方句不变，也不会自动生成。
- 助手回复失败时没有「接着可以」。
