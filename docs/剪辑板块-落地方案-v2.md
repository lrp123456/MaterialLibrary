## 0. 一页结论

**在归档版 OpenCut Classic 的基础上，长出一个贴着现有素材库、能云端分发、能挂 AI 任务的室内空间剪辑台。**

六条已定决策（来自 2026-10-20 的九问）：

| 维度      | 决策                                                             |
| ------- | -------------------------------------------------------------- |
| 代码基线    | fork `OpenCut-app/opencut-classic`（MIT，archived，2026-05-17 冻结） |
| 使用范围    | 内部多机，**预留对外**（加字段不做隔离）                                         |
| 云端角色    | **只读快照仓库**：本地编辑 → 备份上传 → 显式拉取；`rev` 挡并发                        |
| 素材归集    | **引用视图**（关联表 + 删除 409），不物理复制；底层已有 sha256 去重                    |
| 扩展机制    | **声明式资源包**（manifest + shader + 参数 schema），不执行第三方代码             |
| AI / 美颜 | **服务端唯一网关**；浏览器只做纯 shader 美颜                                   |
| 首版      | **闭环优先**：剪得动、存得住、出得来，2–3 周                                     |

**不做什么**（本期）：双向同步、多租户隔离、第三方脚本插件、浏览器端模型推理、时间线实时瘦脸。

## 1. 系统架构

### 1.1 进程拓扑

```text
┌──────────────────────────── 浏览器 ────────────────────────────┐
│  :30002  web-pro (Vue 3 + Vite)                                │
│    /                 素材库 / 创作页 / 成品架                    │
│    /editor/*   ──反代──▶  :3000  editor (Next.js, fork classic) │
│                          basePath=/editor                       │
│                          IndexedDB(工程) + OPFS(素材副本)        │
└───────────────────────────────┬────────────────────────────────┘
                                │ 同源，共享 localStorage.ml_token
┌───────────────────────────────▼────────────────────────────────┐
│  :30001  server.js (Node)                                       │
│    /api/...            现有素材库、上传、AI 任务                 │
│    /editor-api/...     工程快照、资源包、AI 代理、导出帧          │
│    data/material.db    assets / ai_tasks / presets …            │
│    data/clip-packs/    声明式资源包目录                          │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 五条主链路

| 链路       | 走向                                                                          |
| -------- | --------------------------------------------------------------------------- |
| **日常剪辑** | 纯本地：IndexedDB（工程）+ OPFS（素材副本）→ 不碰服务器                                        |
| **备份**   | 校验素材已入库 → `PUT /editor-api/snapshots/:id` → 只传工程 JSON + fid 清单              |
| **拉取**   | `GET /editor-api/snapshots/:id` → 拿工程 JSON → 逐 fid 拉素材 → 写 IndexedDB + OPFS |
| **导出**   | 浏览器合成 → 默认上传 `/api/upload` 进成品库，可切换为本地下载                                    |
| **AI**   | 编辑器提交任务 → `POST /editor-api/ai/tasks` → 轮询 → 结果落为素材 / 字幕轨                   |

### 1.3 代理规则（必须精确）

```js
// web-pro/server.cjs
if (pathname === '/editor' || pathname.startsWith('/editor/')) {
  return proxyRequest(req, res, 'http://127.0.0.1:3000');
}
// ⚠️ 绝不能写 startsWith('/editor')，否则 /editor-api 会被吞掉
```

## 3. 编辑器侧改造

### 3.1 工程存储适配器

```ts
// src/services/storage/http-projects-adapter.ts
export class HttpProjectsAdapter {
  constructor(private base = '/editor-api/snapshots') {}
  private headers() {
    return {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${localStorage.getItem('ml_token') || ''}`,
    };
  }
  async list(): Promise<string[]>          // GET base → items[].id
  async get(id: string): Promise<any>      // GET base/:id → snapshot.data
  async getAll(): Promise<any[]>           // GET base?full=1
  async set(id: string, value: any)        // PUT base/:id（带 rev）
  async remove(id: string)                 // DELETE base/:id
}
```

**四个必须处理的细节**（来自代码事实）：

1. `StorageService.saveProject()` 会自行计算 `duration` 并写 `metadata`——adapter 只负责整份序列化对象，不要二次加工。
2. 我们的快照 id 用 `snap_*` 前缀，与 OpenCut 本地 id（`fe9457-d8a1-…`）分开命名空间，避免混用。
3. `rev` 冲突时抛错，UI 提示"云端有更新版本"，**不自动覆盖**。
4. `services/storage/migrations` 的 `version` 要连续；从 IndexedDB 切服务端时保持同版本号，否则迁移会重跑。

### 3.2 素材库面板

```ts
// 列表：复用现有 viewer 接口
const { items } = await fetch('/api/viewer/assets?kind=video&limit=60', { headers }).then(r => r.json());

// 导入：必须走它原生的 processMediaAssets，才能生成缩略图/波形并落 OPFS
const blob = await fetch(`/api/viewer/assets/${fid}/file`, { headers }).then(r => r.blob());
const file = new File([blob], item.file_name, { type: item.mime });
await processMediaAssets({ files: [file], ... });
```

**不要**改成"只存远程 URL"：渲染器读 `asset.file`（纹理上传、mediabunny 解码都依赖 File/Blob），改造成本远超收益。

**必须做**：面板显示"本地副本占用 X GB"+ 一键清理，否则 OPFS 被 4K 素材撑爆。

### 3.3 导出

```ts
// 默认 mode = 'upload'（对应需求 2：自动同步成品库）
export async function deliverBuffer({ buffer, filename, mimeType, mode = 'upload' }) {
  if (mode === 'download') return downloadBuffer({ buffer, filename, mimeType });
  const form = new FormData();
  form.append('file', new Blob([buffer], { type: mimeType }), filename);
  form.append('shelf', 'finished');
  return fetch('/api/upload', { method: 'POST', headers: authOnly(), body: form }).then(r => r.json());
}
```

UI 上"同步到成品库"默认勾选、可取消；成功后弹出"在成品库查看"链接。

### 3.4 汉化

不做全量 i18n 抽取（会让后续跟进上游变难）。用**运行时字典 + 组件内替换**：

```ts
// src/i18n.ts
const zh = { 'transform.width': '宽度', 'timeline.split': '分割', ... };
export const t = (k: string, fallback?: string) => zh[k] ?? fallback ?? k;
```

首批覆盖：顶部栏、左侧栏 tab、检查器分组标题、时间轴右键菜单、导出弹窗、AI 面板。约 200–300 条。

## 4. 云端与素材（需求 1）

### 4.1 数据模型

新增两张表（`editor_projects` 保留给旧 Vue 编辑器，不再扩展）：

```sql
CREATE TABLE IF NOT EXISTS clip_snapshots (
  id             TEXT PRIMARY KEY,          -- snap_<base36>_<hex>
  name           TEXT NOT NULL,
  owner_id       INTEGER NOT NULL,
  data_json      TEXT NOT NULL,             -- OpenCut SerializedProject
  schema_version INTEGER NOT NULL DEFAULT 1,
  thumbnail_fid  TEXT,
  size_bytes     INTEGER NOT NULL DEFAULT 0,
  rev            INTEGER NOT NULL DEFAULT 1,
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS clip_snapshot_assets (
  snapshot_id TEXT NOT NULL,
  fid         TEXT NOT NULL,
  role        TEXT NOT NULL DEFAULT 'media',  -- media | audio | sticker | font
  created_at  INTEGER NOT NULL,
  PRIMARY KEY (snapshot_id, fid)
);
CREATE INDEX IF NOT EXISTS idx_csa_fid ON clip_snapshot_assets(fid);
```

`assets` 表**不加列**：它已经有 `sha256`、`source`、`category`、`auth_state`，够用。

### 4.2 备份流程（带前置校验）

```text
1. 编辑器收集工程引用的所有 media（project.media[]）
2. 逐个检查是否已有 fid：
   ├─ 有 → 记入清单
   └─ 无（本地新导入）→ 先 POST /api/upload 入库，拿到 fid
3. PUT /editor-api/snapshots/:id
   { name, data, rev, assets: [{fid, role}] }
4. 服务端事务：
   ├─ CAS 校验 rev（不符 → 409 + 最新 rev）
   ├─ upsert clip_snapshots
   └─ 全量重写 clip_snapshot_assets（先删后插，保证清单准确）
5. 返回 { id, rev, updatedAt }
```

**关键规则：能备份的工程，其素材必须全部在服务器有 fid。** 否则别的机器拉下来就是黑块。这条校验在服务端再做一次（清单里有不存在的 fid → 400，列出缺失项）。

### 4.3 拉取流程

```text
GET /editor-api/snapshots            → 列表（含 name/updatedAt/size/assetsCount/thumbnail）
GET /editor-api/snapshots/:id        → { snapshot, assets:[{fid,fileName,kind,size}] }
编辑器侧：
  1. 工程 JSON 写入 IndexedDB（新 id，避免覆盖本地同名）
  2. 对每个 fid：GET /api/viewer/assets/:fid/file → Blob → File → OPFS
  3. 进度条按"素材数量"推进；缺素材不阻断，标红并允许继续
```

**冲突处理**：本地已存在同名工程时**另存副本**（`名称 (云端)`），不覆盖。

### 4.4 素材库板块新增「剪辑素材」

前端新增一个只读 tab，数据来自关联表：

```sql
SELECT a.*, COUNT(cs.snapshot_id) AS used_by
FROM assets a
JOIN clip_snapshot_assets cs ON cs.fid = a.fid
GROUP BY a.fid
ORDER BY used_by DESC, a.updated_at DESC;
```

详情抽屉显示"被 3 个工程使用：客厅漫游 v2 / 卧室案例 / …"。

**删除保护**：现有删除入口统一加一道检查：

```js
const used = db.prepare(`SELECT s.id, s.name FROM clip_snapshot_assets cs
  JOIN clip_snapshots s ON s.id = cs.snapshot_id WHERE cs.fid=?`).all(fid);
if (used.length) throw Object.assign(new Error('素材被剪辑工程引用'), { status: 409, used });
```

## 5. 扩展机制：声明式资源包（需求 3 的底座）

### 5.1 为什么是"包"而不是"插件"

你要的"上千种文字模板 / 大量转场 / 版权素材"，本质是**内容**。声明式包能让内容"丢进目录就生效"，不用发版；而开放脚本在浏览器里跑第三方代码，等于开一个 XSS 后门，内部阶段没必要。

### 5.2 目录与清单

```text
data/clip-packs/
└── com.mls.effect.glow/
    ├── manifest.json
    ├── glow.wgsl
    └── preview.png
```

`manifest.json`（完整 JSON Schema 见 `docs/clip/pack-manifest.schema.json`）：

```json
{
  "schemaVersion": 1,
  "id": "com.mls.effect.glow",
  "type": "effect",
  "name": { "zh": "发光", "en": "Glow" },
  "version": "1.0.0",
  "engine": { "minEditor": "0.1.0" },
  "params": [
    { "key": "intensity", "type": "number", "default": 0.5, "min": 0, "max": 1, "step": 0.01,
      "keyframable": true, "label": { "zh": "强度", "en": "Intensity" } }
  ],
  "render": { "passes": [ { "shader": "glow.wgsl", "uniforms": { "uIntensity": "$intensity" } } ] },
  "preview": "preview.png",
  "license": { "type": "internal", "source": "自研" }
}
```

五种 `type`：`effect` / `transition` / `textTemplate` / `lut` / `sticker`、以及 `assetPack`（批量素材）。

### 5.3 加载与注册

```text
服务端启动：
  扫描 data/clip-packs/*/manifest.json
  → 校验 schema + 计算内容 sha256
  → upsert clip_packs(id, type, version, manifest_json, content_hash, enabled)

编辑器启动：
  GET /editor-api/packs?enabled=1
  → effect/transition：注册进 params/registry + effectPassGroups
  → textTemplate：注册进文字面板模板列表
  → lut/sticker/assetPack：注册进素材面板
```

热更新：`POST /editor-api/packs/reload`（仅本地回环可调）；编辑器下次开页生效。

### 5.4 首批内容清单（M3 交付）

| 类型   | 数量 | 说明                                    |
| ---- | -- | ------------------------------------- |
| 转场   | 8  | 溶解、推移（4 向）、缩放、闪白、擦除、模糊过渡              |
| 画面特效 | 10 | 模糊、发光、锐化、暗角、胶片颗粒、色差、扫描线、老电影、双重曝光、动态模糊 |

## 6. AI 板块（需求 3 的 AI 部分）

### 6.1 前端形态

编辑器左侧栏新增「AI」tab：

- 顶部：可用能力卡片（字幕 / 抠像 / 美颜 / 超分）
- 中部：任务列表（状态、进度、耗时），来自 `GET /editor-api/ai/tasks`
- 底部：提交面板（选素材 → 填参数 → 提交）

结果分两类落法：

- **素材类**（美颜、超分、抠像）：生成新 asset，出现在素材面板，可拖上时间线
- **结构类**（字幕）：直接写入字幕轨，不走素材

### 6.2 服务端

复用现有 `src/ai-tasks.js`（已有 `fid / type / status / progress / payload_json / output_fid / output_kind`），只扩类型：

| type           | 引擎                      | 产出             |
| -------------- | ----------------------- | -------------- |
| `subtitle`     | faster-whisper（本机 3060） | SRT/JSON → 字幕轨 |
| `matting`      | 分割模型（RVM/BiRefNet）      | 带 alpha 的素材    |
| `beauty_pro`   | 人脸关键点 + 磨皮/美白（服务端）      | 新视频素材          |
| `face_reshape` | 关键点 + 网格变形              | 新视频素材          |
| `upscale`      | 已有                      | 新素材            |

新接口（薄封装，内部仍走现有队列）：

```text
POST /editor-api/ai/tasks      { type, fid, params } → { taskId }
GET  /editor-api/ai/tasks/:id  → { status, progress, outputFid?, error? }
GET  /editor-api/ai/tasks?fid= → 列表
POST /editor-api/ai/tasks/:id/cancel
```

### 6.3 美颜的两层实现

| 层   | 能力            | 位置                             | 可调            |
| --- | ------------- | ------------------------------ | ------------- |
| 轻量层 | 磨皮、美白、妆容色调、滤镜 | **浏览器 shader**（作为 effect pass） | 实时、可关键帧       |
| 重量层 | 瘦脸、瘦身、抠像      | **服务端任务**                      | 不可时间线实时，产出新素材 |

**这是必须向使用者说清的产品事实**：想要"拖滑块实时瘦脸"，就得把导出链路搬回服务端重渲，那是另一个量级的工程。

## 9. 风险与回滚

| 风险                     | 概率 | 影响 | 缓解                                                         |
| ---------------------- | -- | -- | ---------------------------------------------------------- |
| WebGPU 不可用             | 中  | 高  | M0 先验；不可用则整条路线重估                                           |
| 两套前端栈（Vue + React）长期维护 | 高  | 中  | 只改接缝文件，业务不碰；i18n 用字典而非全量抽取，降低 rebase 成本                    |
| 浏览器导出长片 OOM            | 中  | 高  | 设时长/分辨率上限并提示；超限引导走服务端逐帧导出                                  |
| OPFS 撑爆                | 高  | 中  | 面板显示占用 + 一键清理 + 导入前配额检查                                    |
| 资源包 schema 漂移          | 中  | 中  | `schemaVersion` + 校验失败拒绝加载 + 保留上一个可用版本                     |
| 版权素材侵权                 | 中  | 高  | `assets.auth_state` 已有授权字段；导入时强制填 `license.source`；对外前做法务核 |
| 上游归档带来的安全漏洞            | 低  | 中  | 不引入新依赖；依赖锁版本；内部网络访问                                        |

**回滚点**：

- M1 完成前，`web-pro` 的旧 `ClipStudio.vue` 保持可用（路由分开）。
- M2 完成后旧编辑器下线，但 `editor_projects` 表与接口保留一个版本周期。
