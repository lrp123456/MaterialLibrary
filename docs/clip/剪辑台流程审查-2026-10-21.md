# 剪辑台流程审查（2026-10-21）

> 触发：用户反馈「左侧素材应区分本次素材与云素材」「只有本次素材能送进剪辑」「云素材库没正确展示」。
> 结论：**一个是真 bug（已修），一个是设计冲突（待改）**。

---

## 1. 云素材库为什么是空的（真 bug，已修）

`src/clip-api.js` 的 `clipAssetsList()` 原实现：

```sql
FROM assets a
JOIN clip_snapshot_assets cs ON cs.fid = a.fid     -- ← 致命
GROUP BY a.fid
```

含义是"**被云端快照引用过的素材**"。没备份过工程的用户，`clip_snapshot_assets` 是空表，
所以列表恒为空——这跟"素材库里有没有素材"无关。

改用素材库全量查询（排除 `status='deleted'`），`used_by` 退化为计数子查询：

```sql
FROM assets a
WHERE a.status <> 'deleted'
-- (SELECT COUNT(*) FROM clip_snapshot_assets cs WHERE cs.fid = a.fid) AS used_by
```

**验证**：内存库造 2 条正常素材 + 1 条 deleted、快照表为空 → 返回 2 条、`total=2`、deleted 被排除。

**生效条件**：需重启 WSL 后端（`./start.sh restart`），因为接口跑在 30001。

## 2. 素材面板是"混排"设计（与要求冲突）

当前实现（另一个会话所改）：

| 位置 | 行为 |
|---|---|
| `views/assets.tsx:90` | 注释写明「云端只读目录：与本地素材在同一个列表里混排，靠 fid 去重」 |
| `media-merged.tsx` `mergeMediaRows()` | 本地 + 云端排序合并成一个列表 |
| `models/assets.tsx` `CloudMediaDraggable` | **云端项可直接拖到时间线** |
| `tab-views.tsx:38` | 媒体子标签：全部 / 图片 / 视频 / 贴纸 / 云端 |

所以现在"本次素材"和"云素材"在"全部"里是混在一起的，且云端项可直接上轨——
正是用户说的两个问题。

## 3. 云端上轨的占位机制（顺带发现的隐患）

`CloudMediaDraggable` 的时序：

1. `dragstart` → 用 `pendingMediaIdForFid(fid)` 临时挂一条内存媒体（id = `pending:<fid>`）；
2. `dragend` → 摘掉临时媒体；若时间线上出现引用该 id 的元素，则并发下载；
3. 下载成功 → 把元素上的 `mediaId` 换成真实 id；失败 → **删除该元素**并 toast。

隐患：

- **id 是确定性的**（`pending:<fid>`），同一个云端素材拖两次会复用同一个 id，
  两条元素共享一个 pending id，先完成的下载会把两条一起替换/删除；
- `dragend` 时临时媒体已被摘除，元素此刻处于"引用了不存在的素材"状态，
  若用户在此期间导出或刷新，落盘的就是坏引用；
- 失败即删元素，用户拖了 3 个只成功 1 个时，另外 2 个会静默消失（仅 toast）。

如果按用户要求"云端素材不允许直接上轨"，这套机制可以整体退居二线
（代码留着，但不再挂到拖拽上），上面的隐患自然消失。

## 4. 建议改动（待确认后执行）

### 4.1 素材栏分组

- "本次素材"：`editor.media.getAssets()` 的本地素材池（本工程上传/导入的）；
- "云素材"：`/editor-api/clip-assets` 的只读列表；
- 两组分别渲染、各自计数，不再 `mergeMediaRows`。

### 4.2 只允许本次素材上轨

- 云端行去掉拖拽外壳，改为 `draggable={false}` + 一个显式的「导入到本次」按钮；
- 按钮复用已有的 `downloadCloudAssetToLocal()`（下载 → 解码 → `addMediaAsset` → 记 fid 映射）；
- 导入完成后该素材出现在"本次素材"里，才可上轨。

### 4.3 云素材库（"云端"子标签）

保持 `LibraryView`，随 4.1 的后端修复自然有数据；补加载失败/空态文案。

### 4.4 风险

这批文件（`assets.tsx` / `media-merged.tsx` / `tab-views.tsx`）**正被另一个会话并行修改**，
改动前需确认没有未提交的工作，避免互相覆盖。
