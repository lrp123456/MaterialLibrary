## 审稿补丁（规范性，优先于后文同题旧句）

### Patch 1 · 预染色不用通道除法

`preTintBasecolor` 禁止 `out = clamp(target * (pixel / mean))` 这种 RGB 三通道独立相除。深色木皮、深色皮革的蓝色通道均值可以低到十几，高光像素一除就会放大数倍，再乘浅色目标就截成 255，纹理变成蓝白噪点。奶油色和高明度目标还会把略高于均值的起伏全部削成纯白。

改为明度残差加软膝：

1. `L = 0.299R + 0.587G + 0.114B`，`Δ = L像素 - L全图平均`。
2. 目标色极亮（`max(T) > 220`）或极暗（`min(T) < 35`）时，压缩系数 `k` 从 0.85 收到 0.35。
3. `Δ` 先过 `tanh` 软膝，再限制在目标色的通道余量内，避免撞 0 或 255。
4. `Out通道 = clamp(round(T通道 + 压缩后的Δ), 0, 255)`。三个通道加同一份明度残差，全图平均色等于目标 HEX，原图色偏被消掉，木纹和石脉的起伏还在。

缓存路径 `cache/base-library/tint/{assetId}_{HEX6}.jpg`。`HEX6` 去掉 `#` 并匹配 `/^[0-9A-F]{6}$/i`。`assetId` 匹配 `/^[a-zA-Z0-9_-]+$/`。`cleanupExpiredDrafts` 在已有 `dataDir` 时顺带删除 `tint/` 里超过 7 天的文件。

### Patch 2 · 参考图编号按实际出图递增，禁止写死图2

`compileBaseAttributes(db, payload)` 增加 `baseImageTag`（默认 `图1`）和 `firstRefIndex`（默认 `2`）。对话侧传入 `totalReferenceCount + 1`。只有真的发出参考图、且没被 `ref_dropped` 截掉的选区，才按顺序得到 `图${n}`，并把这个编号写进该选区自己的句子。两个轨道 B 选区分别是下一张和再下一张，中间的轨道 A 选区不占号。

每个 `region` 自带 `bbox: { x1, y1, x2, y2 }`，整数 0–999。一次 `base_attr` 可以编译多个部位。`edit-run` 在绑定区域没有 bbox 时，才回退到请求级的那一个选区。两者都没有则 400，不调用生图。

### Patch 3 · base_attr 必须贴回，定位句走模型方言

`edit-run.js` 的 `base_attr` 在 `pastebackAllowed && opts.pasteback !== false` 时，生图后调用 `pastebackToTarget`。多选区先并成一个外接矩形再贴回，并计算 `untouchedDiff`。画幅不跟随原图时维持现有规则：不贴回，并在 `regionNote` 说明框外不再逐像素保留。

定位句优先用 `regionClause` 的结果（`coords_bbox` / `coords_point` / `mask` / `vlm_text`）。不支持 `<bbox>` 的模型不在提示词里硬塞坐标。单选区且路由产出蒙版时，把蒙版路径交给 `runAdapter`，与其他 op 相同。

### Patch 4 · 混合选区按 region_id 换句，不全量覆盖

底栏预览和 `buildStructuredPrompt` 在 `guide.type === 'resurface'` 时保留 `<bbox>` 前缀，不再被 `guideSentence` 整句替换掉坐标。

`executeUnifiedApply` 拿到 `compiled.clauses` 后，只按 `region_id` 替换 `resurface` 选区的句子。`replace`、`add`、`erase`、`custom` 的结构化句子原样保留。禁止 `structuredPrompt || compiledPrompt` 这种二选一。

### Patch 5 · 窗帘与地毯拆开，共 8 个部位

`curtain_rug` 取消。部位枚举改为：

1. `ceiling` 顶面
2. `wall` 墙面
3. `floor` 地面硬铺装
4. `millwork` 定制柜体、门板、台面
5. `upholstery` 沙发、软包、餐椅坐面、抱枕
6. `hard_furniture` 桌、茶几、木架、金属件
7. `curtain_bedding` 窗帘、窗纱、床品。只允许 `soft_curtain`、`soft_bedding`。禁止地毯。
8. `rug` 地毯、地垫。只允许 `soft_rug`。禁止窗纱、乳胶漆、石材。

JEV 回退若只能给出旧的 `soft`，结果仍是 `uncertain`，不猜窗帘还是地毯。

### Patch 6 · 顶面色板默认高明度，但可展开全色系

`ceiling` 第一层默认只显示 `lrv >= 70` 的暖白、奶油、冷灰。色板角上有开关「显示全色系（墙顶同色）」，打开后九个色系都可选。默认状态保护新手，开关留给侘寂、暗调和墙顶同色。

### Patch 7 · 柜体第二层按原材质把子类排到前面

`millwork` 的第二层子类始终是这三枚，文案固定为「柜门-烤漆」「柜门-木皮」「台面-石材岩板」。`classifyRegionPart` 的 `material_family` 为 `stone` 时，`mill_stone` 排第一；为 `wood` 或 `paint` 时，木皮和烤漆排在台面前面。用户仍可点另外两枚。

本文取代 `docs/design/基础属性库与创作库计划.md` 里关于「256 色块参考图、灰色底色壳、PaintDB 前 36 条置顶即浏览序、JEV 八装修面直接驱动可选材质」的部分。不重开顶栏、照片素材库瀑布流、风格方案条带、做法库编辑器。`ba_schemes` / `ba_items` 品牌目录继续服务素材库浏览与风格方案，不并进这一轮的编辑器读模型。

## 0. 审计结论（先读这一节）

空间局部换色现在有三条互不写通的路径。

1. **用户实际看到的句子**来自 `region.guide`。`StudioEditLayer.vue` 的「改表皮」只挂 `BaseAttrPicker`（约 1199–1211 行），回写 `onGuideSurface` / `onGuideMaterial` / `onGuideColor`（1822–1858 行）。底栏预览是 `formatGuideRecipe` → `guideSentence`（`web-pro/src/utils/guide-sentence.js` 76–91 行，`StudioEditLayer.vue` 3697 行）。`buildStructuredPrompt` 一旦发现 `reg.guide.type`，就只用这句短句，不再走带 `<bbox>` 的 recolor 分支（`web-pro/src/utils/prompt-engine.js` 151–153 行盖住 164–173 行）。结果是：框选换色的最终提示词没有归一化坐标，也没有「保持原材质褶皱」。

2. **仓库编译器** `compileBaseAttributes`（`src/base-library/compile.js`）只读 `params.baseAttr`。`executeUnifiedApply`（4077–4116 行）把 `baseAttr` 发给 `POST /api/base-library/compile`。全文件只有 `onBaseAttrChange`（2022–2058 行）会写 `params.baseAttr`，模板没有绑定 `@change`。这条编译结果在现行「改表皮」里是空的。`QuickStudio.vue` 用 `v-model="quickBaseAttr"`（563–566 行）才真正打到 `op: 'base_attr'`（2405–2419 行）。

3. **打到模型时的参考图策略是反的。** 色号旗标 `base_library_paints` 默认 1（`schema.js` 261 行）。未勾壳时编译器发 256×256 `swatch.png`（`compile.js` 146–154 行，`swatch.js` `generateSwatchBuffer` 23–33 行）。勾 `use_shell` 时改发 `shell_material_id` 的 1K 底色（`compile.js` 131–144 行）。种子把 10 条色号的壳全部写成 `mat_micro_cement`（`seeds.js` 280 行），而这张壳是 ambientCG `Concrete034` 浅灰水泥（`seeds.js` 208–219 行）。材质参考图另看旗标 `base_library`（`compile.js` 67 行）。该键没有种子，`getFlag` 默认 0（`list.js` 7–13 行），所以材质 1K 默认根本不发。`base_library_compile` 种子是 0（`schema.js` 268 行），编译器和 `edit-run.js` 都不读它。

`op === 'base_attr'`（`src/handlers/edit-run.js` 652–715 行）在计算选区之前就返回。它把整张场景图加上参考图 Base64 交给 `runAdapter`（178–213 行），不写 bbox，不贴回。注释自己写了「基础属性全图重绘」（711 行）。`maxRefs = slotLimit(schema, 'images') - 1`（670–677 行），纯色 PNG 会占掉一个本可用于真纹理的槽。

部位识别仍是 TypeSafe JEV 八选一（`classify.js` `classifyRegionSurface` 114–178 行）。门槛只看 `probabilities[choice] >= 0.75`（43–44、65 行），`confidence` 只打日志。`furniture` 的标准是「桌、椅、床架」，`soft` 是「窗帘、床品、挂画、摆件、绿植」。沙发、软包床没有类。`describeRegion`（`region-vlm.js` 28–36、51 行）是另一条自由文本 VLM，只在模型出口为 `vlm_text` 时由编辑管线调用（`needsVlm` 138–139 行），不能直接当白名单键。

因此五大痛点都在现行代码里，不是印象：

- 色号列表 `ORDER BY pinned DESC, updated_at DESC`（`list.js` 195 行）。置顶规则是 PaintDB 每个品牌插入顺序的前 36 条（`paintdb.js` 104–105 行），中文名是 `deriveChineseName` 的「暖调 + 色系」（31–64 行）。`BaseLibrarySearch.vue` 仍提供立邦约 2720 条、多乐士约 1032 条的镜像按钮（61–88 行）。
- 灰水泥壳与纯色块参考图由 `test/base-library-compile.test.js` 第 41、73–74 行锁死为正确行为。
- `BaseAttrPicker.vue`「切换其他面」展开全部 8 个装修面（21–31 行）。`furniture` / `soft` 只是把子类换成真皮/织物/木皮/金属（168–176 行），用户仍可切到墙面再选乳胶漆。服务端编译不校验部位与资产是否匹配。
- 第一层「只换色、保持原材质」没有独立模式。选中子类后仍要选仓库资产，光泽/粗糙度/做旧叠在同一屏（`BaseAttrPicker.vue` 95–127 行；`material-presets.js` `FINISH_OPTIONS` 109–114、`AGING_OPTIONS` 116–121）。
- 具象库入口是 Poly Haven / ambientCG 每次最多 60 条的在线检索（`ambientcg.js` `searchAmbientCG` 75–107 行，`polyhaven.js` `searchPolyHaven` 24–66 行）。确认入库把标签写死成地面木地板（`BaseLibrarySearch.vue` `importItem` 146 行）。编辑器展示与生图没有稳定的「球预览 / 1K 平铺」分工：`list.js` 124–125 行虽然分了 `preview_url` 与 `basecolor_url`，种子在没有真实文件时用纯色 JPEG 冒充 1K（`seeds.js` 336–350 行）。

并行的 `ba_items`（`items.js` `ensureItemSchema` 30–86 行）是另一套：5 条乳胶漆按色相再按明度排（523–538 行），微水泥是 `kind_key = microcement` 的文字条目（355 行），并且启动时删除玻璃、金属、藤编（143–145 行）。编辑器不读这套表。本计划不把两套表合并，避免把风格方案和品牌爬虫卷进换色修复。

## 2. 基材双轨与数据源排布（板块一）

### 2.1 双轨定义

轨道由**模型需要看见的视觉事实**决定，不由装修面决定。同一部位可以两轨都有，但一次编辑只走一轨。

**轨道 A：色彩与工艺光感（Text + Color + Finish）。参考图恒为 `null`。**

模型从原图选区已经看到平整度、褶皱、接缝。要改的是颜色和光泽语义。再塞一张纯色图或灰水泥图，会覆盖原图证据。

纳入：

- 乳胶漆平涂、蛋壳光、丝光。
- 艺术涂料的**工艺**而不是某一张品牌肌理海报：批刮微水泥、天鹅绒漆、石灰漆、夯土漆。
- 柜门烤漆、肤感纯色膜（没有木纹印刷）。
- 纯色玻璃、电镀金属、均匀拉丝金属。颜色均匀、纹理可用一句话描述。
- 地坪漆、环氧、自流平纯色。
- 第一层「只换色」：无论原材质是皮、布、漆还是木，只要不换品类，都走轨道 A。原图就是材质证据。

标准属性：

```js
{
  track: 'A',
  family_key: 'cream',          // 色系
  display_name: '奶油杏',
  hex: '#F3E6D4',
  lrv: 78,                      // 0–100，亮到暗排序用
  process: 'roller_matte',      // 五工艺之一，可空
  gloss: 'matte'                // matte | eggshell | satin | gloss
}
```

**轨道 B：具象花纹与几何肌理（Image + Text）。必须有真实 1K 平铺，前端用材质球。**

纳入：人眼能认出「就是这一张」的花色或铺法。

- 木地板与木饰面：直纹、山纹、人字拼、鱼骨拼、宽板。词表沿用 `wood-taxonomy.js`。
- 天然石与岩板：鱼肚白、洞石孔洞、特定金脉。纯灰岩如果只是颜色，退回轨道 A。
- 水磨石（骨料可辨）、花砖、壁纸壁布的具体纹样。
- 强识别织物与皮：羊羔绒、千鸟格、特定编织、可辨的油蜡皮粒面。素色平布、素色丝绒的**换色**不进轨道 B。
- 长虹玻璃、木格栅。几何重复必须给图。

不纳入轨道 B、也不再爬进默认库：石膏线模型、灯具、洁具、绿植、挂画。它们是物件替换，不是表皮。

标准属性：

```js
{
```

### 3.1 识别：改用项目内 VLM 的封闭枚举，JEV 只做迁移回退

继续只用 JEV 做不到两件事：它不返回原材质，ontology 里没有沙发。`describeRegion` 的自由文本又不能当白名单键。

新函数放在 `src/base-library/classify-part.js`：

```js
async function classifyRegionPart(db, cropJpegBuffer, options) → {
  part,            // 8 键之一或 null
  material_family, // paint | art_coat | wood | stone | leather | fabric | metal | glass | unknown
  probability,     // 0–1
  uncertain        // probability < 0.75 或枚举非法
}
```

实现：复用 `region-vlm.js` 的治理台终点（`resolveVlmEndpoint` + `chatVision`），提示词改为只返回 JSON：

```json
{"part":"upholstery","material_family":"leather","probability":0.86}
```

`part` 只允许第 3.2 节的 8 个键。`material_family` 只允许上面的 9 个词。解析失败或概率低于 0.75 时 `uncertain: true`，与现在 JEV 的门槛一致，但比较的是这一次封闭回答的概率，不再误用 JEV 的 `confidence` 字段。

裁切继续用 `cropSelectionInterior`（选区内部、不外扩）。`routes.js` `classify-region`（756–816 行）在 `crop_base64` 与服务端裁切之后改调 `classifyRegionPart`。响应里保留旧字段 `surface` 一个版本：按映射表填，供尚未改完的前端读取。

映射只用于回退显示，不用于开放材料：

| ceiling | ceiling |
| wall | wall |
| floor | floor |
| millwork | millwork |
| upholstery | furniture |
| hard_furniture | furniture |
| curtain_bedding | soft |

JEV 不能区分 `upholstery` 与 `hard_furniture`。因此 `base_library_jev` 回退路径在 `furniture` 或 `soft` 上必须返回 `uncertain: true`，强迫用户点一次部位，而不是把沙发默认为桌椅或把窗帘默认为摆件。`lighting` / `fixture` 不再出现在换色识别结果里；若 VLM 判成灯具或五金，`part = null`，前端提示改走「增 / 改物件」。

`compileBaseAttributes(db, payload)` 保持入口，内部按区调用新函数：

```js
function compileRegion(db, region) → {
  region_id,
  text,
  reference,   // null | { kind: 'basecolor', rel, tinted: false }
  track,       // 'A' | 'B'
  warnings     // string[]
}
```

规则：

| 条件 | reference | 提示词要点 |
| --- | --- | --- |
| `mode === 'recolor'`，或轨道 A（漆、工艺、纯色金属、纯色玻璃、烤漆） | `null`。不调用 `ensurePaintSwatchFile`，不读 `shell_material_id`，不读 `swatch_rel` | 部位 + 原材质族 + 色名 + HEX + 工艺。明确写「不要贴色块，不要把参考图的灰色水泥铺上去」。此时 images 数组只有场景图。 |
| 轨道 B 且没有 `hex` | `{ kind: 'basecolor', rel: basecolor_rel, tinted: false, refImageTag }` | 「纹理与铺法对齐${refImageTag}」。编号见 Patch 2，禁止写死图2。 |
| 轨道 B 且有 `hex` | 同一条，`tinted: true`，`edit-run` 发送预染色结果 | 「${refImageTag}已经是目标颜色，不要再改色。」 |

`compileBaseAttributes` 入参增加 `baseImageTag` 与 `firstRefIndex`。占号只发生在参考图实际留下之后。

`use_shell` 入参忽略。旧客户端再传 `true` 也走轨道 A 文字，并 `warnings.push('shell_ignored')`。

参考图张数仍受 `slotLimit - 1` 约束（`edit-run.js` 670–677 行）。超出时保留 `ref_dropped`：丢图、留文字，并且该区不占图号。轨道 A 不再占槽。

### 5.2 预染色

新文件 `src/base-library/pretint.js`：

```js
async function preTintBasecolor(inputBuffer, hex) → Buffer
```

算法以文首 Patch 1 为准，禁止通道除法。摘要：

1. `sharp` 解码为 sRGB raw，边长限制 1024。
2. 用感知明度做中心化残差 `Δ = L像素 - L平均`。
3. 极亮或极暗目标把增益 `k` 收到 `[0.35, 0.85]`，残差再过 `tanh`，并限制在目标色余量内。
4. 三个通道都是 `目标通道 + 同一份残差`。平均色等于目标 HEX，弱通道不会单独爆成 255。
5. 输出 JPEG quality 90。

艺术漆五工艺不走预染色。缓存文件名与 7 天清理见 Patch 1。不回写 `ba_materials.basecolor_rel`。

### 5.3 执行层要补上选区

`base_attr` 在调用适配器之前，对每个区域走 `regionClause`（`src/handlers/region-route.js`）。定位句用返回的 `areaPhrase` / `text`，不在本文件再写死 `<bbox>`。没有选区则抛「未指定有效选区」，不调用生图。

生图后，当 `pastebackAllowed && opts.pasteback !== false`，调用 `pastebackToTarget`。多个选区先并成外接矩形。随后用该范围计算 `untouchedDiff`。单选区若路由给出蒙版，`maskPath` 传给 `runAdapter`。

images 顺序：场景图，然后按 `refImageTag` 顺序的 1K 或预染色 JPEG。

`getFlag(db, 'base_library')` 删除。轨道 B 是否发图只看条目有没有合法 `basecolor_rel`。色号旗标不再决定发色块。

### 6.1 风险

- 封闭 JSON 的 VLM 会有概率低于 0.75 的空识别。空识别时必须让用户选部位，不得回退成「八个面全开」。

- `executeUnifiedApply` 与 `guide` 脱节是现行 bug。Stage 3 若只改抽屉、不改 4077 行的读取字段，用户仍会看到新 UI、发出旧的空编译。该行与抽屉放在同一阶段。
- `base-library-compile` 旧断言会在 Stage 1 故意失败。先改测试再改编译器，避免有人把断言改回 swatch。
