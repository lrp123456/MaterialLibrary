# 剪辑板块生产化改造计划

> 版本：v1.0（2026-10-19）
> 范围：`MaterialLibraryServer` / `web-pro` 多轨剪辑板块 + 创作页参数配置
> 方法：源码审计 + REA 6.7.0 静态证据分析 + 剪映草稿格式对照 + OpenCut Classic 架构拆解
> 状态：**待评审**。评审通过后按第 6 章路线图执行。

---

## 0. 一页结论

当前剪辑板块**不能称为生产可用**，差距不在"功能少"，而在三处地基：

1. **渲染地基不稳**：`compositor` 与第一块 canvas 永久绑定，切换页面/重开工程后预览与导出全部黑屏（P0-1）；导出与播放共用同一块画布和渲染令牌（P0-2）。
2. **数据地基不稳**：工程保存无版本号、无冲突检测、无修订快照，多端/多标签页后写覆盖先写（P0-3）；关页 `keepalive` 发整份工程，超过 64 KiB 直接丢（P1-5）。
3. **部署链路断裂**：30002 入口只代理 `/api`，不代理 `/editor-api`，从面板启动时剪辑接口返回 HTML，工程列表/保存/导出全挂（P0-4）。

同时存在一个**安全 P0**：`sessionId` 允许 `..`，一次 assemble 会递归删除整个导出根目录（P0-5）。

REA 对照结论：OpenCut 值得借的是**分层与命令化**（EditorCore + Command 栈 + 参数注册表），剪映值得借的是**草稿数据模型**（微秒时间基、materials 资源池、`target_timerange`/`source_timerange` 分离、`extra_material_refs`）。两者都不建议照搬 UI。

改造分三期：**P0 止血（1–2 天）→ P1 生产可用（2–3 周）→ P2 体验与性能（3–4 周）**。P0 已在本次提交中落地，P1/P2 待评审后执行。

### 1.3 能力基线（当前真正能做到 / 做不到）

**能做到**

- 单场景多轨（V/T/G/E/A）叠加，视频/图片/文字/贴纸/图形/效果轨
- 片段移动、左右修剪、切分、波纹删除、闭合间隙、吸附、书签
- 变换 5 参数关键帧（线性/贝塞尔/保持）、矩形/椭圆/贝塞尔遮罩、片段模糊
- 变速（0.5×–4×）、音量/淡入淡出、视频原声分离为音频片段（非链接）
- 逐帧渲染导出 MP4（受 1.4 节缺陷影响，结果可能不可信）

**做不到（不是"做得不好"，是"没有"）**

- 本地素材导入、多选/框选、跨轨拖拽、插入/覆盖/波纹/滚动/滑移编辑
- 帧级量化与时间码输入、入出点与区间导出、转场
- 音画链接（linkId）、轨道级音量/独奏/电平表
- 调色/LUT/混合模式/裁剪/色键、文字富排版
- 片段复制粘贴、代理媒体、帧缓存、导出队列/后台作业
- 多场景串联导出（只导出当前激活场景）

### 3.2 OpenCut Classic 拆解

**分层**

```text
apps/web/src/
├── core/                EditorCore：项目/时间轴/播放/渲染/选区/保存/剪贴板/诊断
│   └── managers/        timeline-manager, playback-manager, renderer-manager, save-manager…
├── commands/            所有变更 = Command 对象（可撤销、可批处理）
│   ├── timeline/element/insert-element.ts, delete-elements.ts, duplicate-elements.ts
│   ├── timeline/element/keyframes/*, masks/*, effects/*
│   └── scene/*, project/*
├── timeline/            纯 UI 交互层：controllers（drag/resize/seek/zoom）+ components
├── params/              参数注册表：类型、默认值、min/max/step、是否可关键帧
├── panels/              属性面板由 registry 驱动，不写死字段
├── export/              导出参数枚举（format/quality/fps/includeAudio）
└── media/ db/ storage/  媒体资产与持久化
```

**数据模型（`timeline/types.ts`）**

```ts
interface TScene { id; name; isMain; tracks: SceneTracks; bookmarks: Bookmark[] }
interface SceneTracks { overlay: OverlayTrack[]; main: VideoTrack; audio: AudioTrack[] }
interface BaseTimelineElement {
  id; name;
  duration: MediaTime; startTime: MediaTime;
  trimStart: MediaTime; trimEnd: MediaTime;
  sourceDuration?: MediaTime;
  animations?; params: ParamValues;
}
type TimelineElement = Audio | Video | Image | Text | Sticker | Graphic | Effect
```

**关键设计**

1. **主轨/覆盖轨/音频轨显式分区**：`main` 唯一，`overlay` 有序数组，`audio` 数组。层级由数组顺序决定，不靠 `isMain` 标志位。
2. **参数统一进 `params`**：`transform.positionX/scaleX/rotate`、`opacity`、`blendMode`、文字 `content/fontSize/color` 全部是注册表项，检查器按 registry 渲染，渲染器按 key 求值。
3. **命令化撤销**：每个操作是 `Command`，支持 batch 与 preview tracker（拖拽中实时预览、松手才提交一条历史）。
4. **时间用 `MediaTime`**（有理数/帧基），不是 float 秒。
5. **交互控制器拆分**：drag / resize / seek / zoom / keyframe-drag 各自独立，时间轴组件只负责画。

### 3.3 剪映拆解（草稿格式层）

**顶层**

```json
{
  "canvas_config": { "width": 1920, "height": 1080, "ratio": "original" },
  "fps": 30.0,
  "duration": 7000000,          // 微秒
  "config": { "maintrack_adsorb": true },
  "materials": { "videos": [], "audios": [], "texts": [], "masks": [], "effects": [], "filters": [], "transitions": [] },
  "tracks": [ { "type": "video", "segments": [] } ]
}
```

**片段（segment）**

```json
{
  "id": "...",
  "material_id": "...",
  "target_timerange": { "start": 0, "duration": 5000000 },
  "source_timerange":  { "start": 1000000, "duration": 5000000 },
  "speed": 1.0,
  "volume": 1.0,
  "visible": true,
  "clip": { "transform": { "x": 0, "y": 0 }, "scale": { "x": 1, "y": 1 }, "rotation": 0, "flip": {...} },
  "common_keyframes": [ { "property_type": "KFTypePositionX", "keyframe_list": [...] } ],
  "extra_material_refs": ["mask_id", "transition_id", "effect_id"]
}
```

**关键设计**

1. **素材池与片段分离**：`materials` 是全局资源池，片段只存 `material_id`；遮罩/转场/特效/滤镜通过 `extra_material_refs` 挂到片段，不内联。
2. **双时间区间**：`target_timerange`（时间轴位置）与 `source_timerange`（源素材窗口）分离，变速/修剪不会混淆。
3. **微秒整数时间**：避免 float 累积误差；帧率只影响渲染，不影响存储。
4. **文字样式是富结构**：`content`（富文本 JSON）+ `font` + `styles`（size/bold/italic/underline/strokes）+ `shadows` + `background_*` + `alignment/letter_spacing/line_spacing`。
5. **遮罩是独立材质**：`config` 里 `centerX/centerY/width/height/rotation/feather/roundCorner/invert`，可复用。
6. **色键独立对象**：`chroma`（color/intensity/shadow/edge_smooth/spill）。
7. **特效/滤镜带参数数组**：`adjust_params` 是 `{key, value}` 列表，天然支持注册表驱动 UI。

### 3.4 三方对比

| 维度 | 当前系统 | OpenCut Classic | 剪映草稿 |
|---|---|---|---|
| 时间基 | float 秒 | `MediaTime`（帧/有理数） | 整数微秒 |
| 轨道模型 | 扁平 `tracks[] + isMain` | `main/overlay/audio` 显式分区 | `tracks[] + type` |
| 资源引用 | 片段内联 `mediaId` + url | `mediaId` + 媒体库 | `material_id` + materials 池 |
| 参数系统 | 分散字段 + 手写检查器 | `params` + registry 驱动 | 材质字段 + `adjust_params` |
| 撤销 | 全量 JSON 快照 ×100 | Command + batch | 无（宿主应用管理） |
| 时间轴交互 | 组件内 pointer 逻辑 | controllers 分层 | 闭源，交互成熟 |
| 关键帧 | 相对片段，5 个变换属性 | 任意 param key + 曲线编辑器 | `common_keyframes` 多属性 |
| 遮罩 | 片段内联数组 | `masks[]` + 自定义点 | 独立材质 + 可复用 |
| 转场 | 无 | 有 | 有（`transitions` 材质） |
| 音频 | `<audio>` 元素 + 服务端 WAV | 统一音频图 | 多轨 + 音量/淡化 |
| 导出 | 浏览器逐帧 JPEG → ffmpeg | 浏览器内编码（WebCodecs/WASM） | 桌面端原生编码 |
| 工程持久化 | 单行 JSON，无版本 | IndexedDB + 命令日志 | 本地草稿目录 |

### 3.5 采纳 / 改造 / 不采纳

**直接采纳**

- `main/overlay/audio` 分区（改造现有 `isMain`，保留兼容层）
- `params` + 注册表驱动检查器（把现有 5 个变换字段扩成可注册参数）
- Command 栈（替代全量快照；拖拽合并为一条）
- `target/source` 双区间（现有 `start/duration/trimStart/trimEnd` 语义已接近，补齐"源长度"约束）
- 素材池与片段分离（现有 `media[]` 已是池，需补 `materialRef` 与资源类型）

**改造后采纳**

- 微秒时间基：**不直接改存储单位**（迁移风险大），改为在渲染/导出边界量化到帧，存储保留秒但增加 `frame` 派生字段。
- 材质 `extra_material_refs`：改为 `refs: { maskIds, effectIds, transitionId }`，避免字符串数组不可读。
- 命令化：先覆盖高风险操作（移动/修剪/切分/删除/参数），不追求一次性全量。

**不采纳**

- OpenCut 的 React/TanStack 技术栈与 WASM 编码链路：当前是 Vue + 服务端 ffmpeg，替换成本高于收益。
- 剪映的闭源特效 ID 体系：无法合法复用资源。
- 剪映的微秒整数全量迁移：需要重写所有求值逻辑，收益不足以抵消风险。

### 4.4 命令栈

```js
class CommandStack {
  execute(cmd)     // { label, apply(project), invert(project) } 或 { before, after }
  undo() / redo()
  batch(label, cmds)
  coalesce(key, ms) // 连续拖拽 300ms 内合并为一条
}
```

迁移顺序：`deleteClip` → `split` → `move` → `trim` → `updateParam` → `addMask`。每迁一个，删除对应 `pushHistory` 调用。

### 4.5 渲染管线

- **离屏池**：按 `w×h` 复用 canvas，不再每帧 `createElement`。
- **帧缓存**：同一 `(clipId, frameNo)` 的合成结果缓存 LRU 32 帧，拖动时复用。
- **DPR 分离**：预览按 `min(canvas.width, viewport*dpr)` 渲染；导出按工程分辨率。
- **seek 阈值**：改为 `0.4 / fps`，并优先 `requestVideoFrameCallback`。
- **视频池按 `(url, clipId)` 分配**，同一素材多片段不共享 `currentTime`。
- **时间量化**：`frame = Math.round(t * fps)`，求值前统一 `t = frame / fps`。

### 4.6 音频

- 统一 `AudioContext` 图：`MediaElementSource → GainNode → Destination`，预览与导出共用一套增益/淡化曲线。
- 片段 `linkId` 联动：移动/修剪/切分/变速同时作用于视频与音频。
- 波形峰值缓存：按 `mediaId + 分辨率桶` 缓存 min/max 数组，修剪不再重算 PCM。

### 4.7 持久化

| 项 | 方案 |
|---|---|
| 乐观锁 | `editor_projects.rev` 自增；PUT 带 `If-Match: rev`，冲突返回 409 + 服务端最新 rev |
| 修订快照 | 每 20 次保存或每 5 分钟写 `editor_project_revisions`，保留最近 20 份 |
| 关页保存 | `navigator.sendBeacon` 只发**增量补丁**（若实现成本高，则限制为最近 32 KiB 关键字段 + 下次打开提示） |
| 损坏兜底 | `JSON.parse` 失败返回 500 + 原始备份，不返回空工程 |
| 分片 | 大工程按 `scenes[i]` 分片存储，降低单行体积（P2） |

### 4.8 导出作业化

```text
POST /editor-api/export/jobs        → { jobId }         创建作业（落库 owner/projectId/fps/format）
GET  /editor-api/export/jobs/:id    → { status, progress, stage }
POST /editor-api/export/jobs/:id/cancel → kill ffmpeg
POST /editor-api/export/frame?job=&index=  → 上传帧（校验 JPEG 魔数 + 会话归属）
POST /editor-api/export/jobs/:id/finish     → 启动 ffmpeg，异步推进度
```

- 并发上限 2，队列 FIFO。
- 失败/取消统一 `finally` 清理帧目录与半成品。
- 输出名带 `jobId` 短码，避免同秒覆盖。
