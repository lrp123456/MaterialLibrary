### 根因

- `editor/apps/web/.gitignore` 只忽略 `.next/`，**没有**忽略我用 `NEXT_DIST_DIR` 生成的 `.next-buildN/`；
- 根 `.gitignore` 也没有 `.next*` 规则；

### 影响

1. 仓库体积永久膨胀（即使后续删除，历史里仍在）。
2. **source map 会还原完整源码**，包括服务端 chunk 与我们的改造（虽然不是密钥，但暴露实现细节）。
3. 克隆/拉取变慢，CI 与备份成本上升。

### 已做

根 `.gitignore` 追加：

```gitignore

.next-build*/
editor/apps/web/.next*/
```

已验证 `.next/` 生效；**已跟踪的 4064 个文件需要 `git rm --cached` 才会停止跟踪**（见第 5 节）。

3. 若 `<公网IP>` 暴露了 `30001`，**先关端口映射**，再改密码。

### 5.2 清理历史（需要单独确认，属破坏性操作）

> 会重写全部 commit hash，已推送的分支需要 force push；协作者必须重新 clone。

```bash
# 0) 先做镜像备份
git clone --mirror . ../MaterialLibrary.git.bak

# 1) 从所有提交里移除构建产物
git filter-branch --force --index-filter \
  'git rm -r --cached --ignore-unmatch \
     editor/apps/web/.next-build1 editor/apps/web/.next-build2 \
     editor/apps/web/.next-build3 editor/apps/web/.next-build4' \
  --prune-empty --tag-name-filter cat -- --all

# 2) 抹掉账号字符串
git filter-branch --force --tree-filter \
  "grep -rl '5043****19' . --exclude-dir=.git 2>/dev/null | xargs -r sed -i 's/5043****19/REDACTED/g'" \
  --prune-empty --tag-name-filter cat -- --all

# 3) 清理引用与对象
git for-each-ref --format='delete %(refname)' refs/original | git update-ref --stdin
git reflog expire --expire=now --all
git gc --prune=now --aggressive

# 4) 强推
git push --force --all
git push --force --tags
```

**注意**：force push 后 GitHub 仍可能通过旧 commit SHA 访问对象一段时间。
最稳妥的做法是**删除并重建仓库**（代码本地都有，重建成本低于清理成本）。

### 5.3 复发防护

1. 提交前自查（放进 `.git/hooks/pre-commit` 或本地脚本）：
   ```bash
   git diff --cached -U0 | grep -nE '(sk-[A-Za-z0-9]{16,}|AKIA[0-9A-Z]{16}|PRIVATE KEY|5043****19)' && {
     echo "疑似敏感信息，已阻止提交"; exit 1; }
   ```
2. 账号/口令一律走环境变量：本次已把 4 个脚本改成 `ML_USER` / `ML_PASSWORD`。
3. 部署地址改环境变量，`.env.example` 保留占位。
